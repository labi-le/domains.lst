| `tiktok-custom-dns` | `/etc/init.d/tiktok-custom-dns` | Writes `/tmp/dnsmasq.d/04_tiktok_custom_dns.lst`; installed on the router but the generated file is absent, so it has not run since the last boot. **Diverged, router is ahead**: repo md5 `d3ae3f5599d12925099cfb80a82028bf` vs router `cf2cbb9e9e5849dee880beef9dc83f7e`. ## Workstation Tools

| repo path | runs on | role |
| --- | --- | --- |
| `trace-app-domains.sh` | workstation (LAN client), not the router | Traces which hosts a process tree talks to so its domains can be added to a rule list: `tshark -i any -f 'udp port 53'` for the names, polled `ss -tunpH` for the peers of the traced PIDs, joined by IP. Needs `bash`, `tshark` and a `ss` that reports PIDs — none of which the router's busybox userland provides. It derives the fake-IP range from `fake-ip-range` in `mihomo/config.yaml` (override with `MIHOMO_CONF`) and matches a peer numerically against the whole CIDR instead of the hardcoded `198.18.1.` prefix it used to carry, so with the pool at `198.18.0.0/16` an address like `198.18.7.9` is reported as already inside mihomo rather than as a raw-IP destination |
